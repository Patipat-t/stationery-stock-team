# Spec: ฟีเจอร์แจ้งเตือนสต็อกต่ำ และรายงานมูลค่าสต็อก

## 1. เป้าหมาย (Goal)
เพิ่มความสามารถให้ระบบ inventory แจ้งเตือนผู้จัดการเมื่อสินค้าใดต่ำกว่า
threshold และให้ผู้จัดการดูรายงานมูลค่าสต็อกแยกตามหมวดหมู่ได้

## 2. User Story
| รหัส | User Story |
|---|---|
| US-01 | As a พนักงานคลังสินค้า, I want บันทึกการรับ/จ่ายสินค้าพร้อมอัปเดตสต็อกทันที, so that สต็อกในระบบสะท้อนจำนวนจริง |
| US-02 | As a ผู้จัดการ, I want รับการแจ้งเตือนทันทีเมื่อสินค้าใดต่ำกว่า threshold, so that สั่งซื้อได้ก่อนของหมด |
| US-03 | As a ผู้จัดการ, I want ดูมูลค่ารวมของสต็อกแยกตามหมวดหมู่, so that ตัดสินใจด้านการเงินได้ |
| US-04 | As a ผู้จัดการ, I want กำหนดค่า threshold สต็อกต่ำแยกรายสินค้าได้, so that เหมาะสมกับอัตราการใช้งานของสินค้าแต่ละชนิด |
| US-05 | As a ผู้จัดการ, I want เลือกลงทะเบียนช่องทางการแจ้งเตือน (Email, SMS) ได้หลายช่องทางพร้อมกัน, so that ได้รับข้อมูลผ่านช่องทางที่สะดวก |

## 3. Acceptance Criteria (Given-When-Then)
### AC ของ US-02 (ตัวอย่างที่ผู้สอนกำหนด)
```gherkin
Scenario: จ่ายสินค้าจนสต็อกต่ำกว่า threshold
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 20 เมตร และ threshold = 15
  When พนักงานบันทึกจ่ายออก 8 เมตร
  Then สต็อกคงเหลือ 12 เมตร
  And ระบบส่งการแจ้งเตือนถึงผู้จัดการว่าสต็อกต่ำ

Scenario: จ่ายสินค้าโดยสต็อกยังสูงกว่า threshold
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 50 เมตร และ threshold = 15
  When พนักงานบันทึกจ่ายออก 10 เมตร
  Then สต็อกคงเหลือ 40 เมตร
  And ระบบไม่ส่งการแจ้งเตือน
```

### AC ของ US-01 และ US-03 (เติมเอง อย่างน้อย 2 scenario ต่อ story)
```gherkin
Scenario: รับสินค้าเข้าคลังสำเร็จ (US-01)
  Given สินค้า "ท่อ PVC 1/2 นิ้ว" มีสต็อกปัจจุบัน 10 ชิ้น
  When พนักงานบันทึกรับเข้า 15 ชิ้น
  Then สต็อกคงเหลือกลายเป็น 25 ชิ้น

Scenario: จ่ายสินค้าเมื่อสต็อกไม่เพียงพอ (US-01)
  Given สินค้า "ท่อ PVC 1/2 นิ้ว" มีสต็อกปัจจุบัน 5 ชิ้น
  When พนักงานพยายามบันทึกจ่ายออก 10 ชิ้น
  Then ระบบต้องปฏิเสธคำขอและแสดงข้อผิดพลาดว่าสินค้าไม่เพียงพอ
  And สต็อกคงเหลือยังคงเป็น 5 ชิ้นเท่าเดิม

Scenario: คำนวณมูลค่ารวมแยกตามหมวดหมู่ที่มีสินค้า (US-03)
  Given มีสินค้าหมวด "ไฟฟ้า" 2 รายการ:
    | สินค้า | จำนวนคงเหลือ | ราคาต่อหน่วย (บาท) |
    | สายไฟ | 10 | 100 |
    | เบรกเกอร์ | 5 | 200 |
  When ผู้จัดการเรียกดูรายงานมูลค่าสต็อกแยกตามหมวดหมู่
  Then ระบบแสดงมูลค่ารวมของหมวด "ไฟฟ้า" เท่ากับ 2,000.0 บาท

Scenario: รายงานหมวดหมู่ที่ไม่มีสินค้าคงเหลือ (US-03)
  Given หมวดหมู่ "ประปา" ไม่มีรายการสินค้าคงคลังคงเหลือ
  When ผู้จัดการเรียกดูรายงานมูลค่าสต็อกแยกตามหมวดหมู่
  Then หมวด "ประปา" ต้องแสดงมูลค่ารวม 0.0 บาท
```

## 4. In Scope / Out of Scope
**In Scope:** บันทึกรับ/จ่าย + อัปเดตสต็อกใน memory, แจ้งเตือน email/sms (print แทนส่งจริง), รายงานมูลค่าแยกหมวด, กำหนด threshold รายสินค้า[cite: 1]
**Out of Scope:** ส่ง email/sms จริง, ระบบ login/สิทธิ์, ฐานข้อมูลถาวร (ใน lab นี้จัดเก็บข้อมูลใน memory ชั่วคราว ไม่บันทึกลง Database จริง)[cite: 1]

## 5. Functional Requirements (FR)
| รหัส | ความต้องการ | จาก Story |
|---|---|---|
| FR-01 | ระบบต้องอัปเดตสต็อกทันทีหลังบันทึกรับ/จ่าย | US-01 |
| FR-02 | ระบบต้องตรวจสต็อกก่อนจ่าย และปฏิเสธถ้าไม่พอ | US-01 |
| FR-03 | ระบบต้องแจ้งเตือนเมื่อสต็อกหลังจ่ายต่ำกว่า threshold | US-02 |
| FR-04 | ระบบต้องคำนวณผลรวม (สต็อกคงเหลือ x ราคาต่อหน่วย) จัดกลุ่มตามหมวดหมู่สินค้า | US-03 |
| FR-05 | ระบบต้องรองรับการกำหนดค่า threshold สำหรับสินค้าแต่ละรายการ | US-04 |

## 6. Non-Functional Requirements (NFR)
| รหัส | มิติ | ความต้องการ (ต้องวัดได้) |
|---|---|---|
| NFR-01 | Performance | รายงานมูลค่าสต็อก 1,000 รายการเสร็จภายใน 1 วินาที |
| NFR-02 | Maintainability | เพิ่มช่องทางแจ้งเตือนใหม่ได้โดยไม่แก้ business logic เดิม |
| NFR-03 | Reliability | ระบบต้องทำงานถูกต้อง ไม่ส่งการแจ้งเตือนผิดพลาดเมื่อสต็อกเท่ากับ threshold พอดี |

## 7. Design Notes
- การแจ้งเตือนต้องแยกออกจาก business logic ของสต็อก[cite: 1]

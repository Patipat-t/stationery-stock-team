# Spec: ฟีเจอร์แจ้งเตือนสต็อกต่ำ และรายงานมูลค่าสต็อก

## 1. เป้าหมาย (Goal)
เพิ่มความสามารถให้ระบบ inventory แจ้งเตือนผู้จัดการเมื่อสินค้าใดต่ำกว่า
threshold และให้ผู้จัดการดูรายงานมูลค่าสต็อกแยกตามหมวดหมู่ได้

## 2. User Story
| รหัส | User Story |
|---|---|
| US-01 | As a พนักงานคลังสินค้า, I want บันทึกการรับ/จ่ายสินค้าพร้อมอัปเดตสต็อกทันที, so that สต็อกในระบบสะท้อนจำนวนจริง |
| US-02 | As a ผู้จัดการ, I want รับการแจ้งเตือนทันทีเมื่อสินค้าใดต่ำกว่า threshold, so that สั่งซื้อได้ก่อนของหมด |
| US-03 | As a ผู้จัดการ, I want ดูมูลค่ารวมของสต็อกแยกตามหมวดหมู่, so that ตัดสินใจด้านการเงินได้ |
| US-04 | As a ผู้จัดการ, I want กำหนดค่า threshold ขั้นต่ำแยกรายสินค้าได้, so that สินค้าที่มีรอบสั่งซื้อต่างกันได้รับการเตือนที่เหมาะสม |
| US-05 | As a ผู้จัดการ, I want เลือกช่องทางการรับแจ้งเตือนได้ว่าจะรับทาง email หรือ sms, so that ได้รับข้อมูลผ่านช่องทางที่สะดวกที่สุด |

## 3. Acceptance Criteria (Given-When-Then)
### AC ของ US-02 (การแจ้งเตือนสต็อกต่ำ)
Scenario: จ่ายสินค้าจนสต็อกต่ำกว่า threshold
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 20 เมตร และ threshold = 15
  When พนักงานบันทึกจ่ายออก 8 เมตร
  Then สต็อกคงเหลือ 12 เมตร
  And ระบบส่งการแจ้งเตือนถึงผู้จัดการว่าสต็อกต่ำ

Scenario: จ่ายสินค้าโดยสต็อกยังสูงกว่า threshold
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 50 เมตร และ threshold = 15
  When พนักงานบันทึกจ่ายออก 10 เมตร
  Then สต็อกคงเหลือ 40 เมตร
  And ระบบไม่ส่งการแจ้งเตือน

Scenario: จ่ายสินค้าจนสต็อกเท่ากับ threshold พอดี
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 20 เมตร และ threshold = 15
  When พนักงานบันทึกจ่ายออก 5 เมตร
  Then สต็อกคงเหลือ 15 เมตร
  And ระบบต้องไม่ส่งการแจ้งเตือน (เงื่อนไขแจ้งเตือนคือ สต็อก < threshold เท่านั้น)

### AC ของ US-01, US-03, US-04, US-05
Scenario: บันทึกรับสินค้าเข้าสต็อกสำเร็จ
  Given สินค้า "ปากกาเคมี" มีสต็อกเดิม 10 ด้าม
  When พนักงานบันทึกรับเข้า 15 ด้าม
  Then สต็อกคงเหลือใหม่ต้องเป็น 25 ด้าม
  And ข้อมูลสต็อกในระบบถูกบันทึกทันที

Scenario: บันทึกจ่ายสินค้าออกแต่จำนวนคงเหลือไม่เพียงพอ
  Given สินค้า "กระดาษ A4" มีสต็อกเดิม 5 รีม
  When พนักงานพยายามบันทึกจ่ายออก 10 รีม
  Then ระบบต้องปฏิเสธการทำรายการและแสดงข้อผิดพลาดว่าสินค้าไม่เพียงพอ
  And สต็อกคงเหลือต้องยังคงเป็น 5 รีมเท่าเดิม

Scenario: เรียกดูรายงานมูลค่าสต็อกเมื่อมีสินค้าหลายหมวดหมู่
  Given ในระบบมีสินค้าหมวด "ไฟฟ้า" รวมมูลค่า 5,000 บาท และหมวด "เครื่องเขียน" รวมมูลค่า 2,000 บาท
  When ผู้จัดการเรียกดูรายงานมูลค่าสต็อกแยกตามหมวดหมู่
  Then ระบบต้องแสดงรายงานแยกหมวด "ไฟฟ้า: 5,000 บาท" และ "เครื่องเขียน: 2,000 บาท"
  And ระบบต้องแสดงมูลค่ารวมทั้งหมดเท่ากับ 7,000 บาท

Scenario: เรียกดูรายงานมูลค่าสต็อกเมื่อไม่มีสินค้าในระบบ
  Given ในระบบไม่มีข้อมูลสินค้าคงเหลืออยู่เลย
  When ผู้จัดการเรียกดูรายงานมูลค่าสต็อกแยกตามหมวดหมู่
  Then ระบบต้องแสดงข้อความ "ไม่มีสินค้าในระบบ"
  And มูลค่ารวมของทุกหมวดหมู่ต้องแสดงเป็น 0 บาท

## 4. In Scope / Out of Scope
- **In Scope:** บันทึกรับ/จ่าย + อัปเดตสต็อกใน memory และ stock.json, แจ้งเตือน email/sms (print แทนส่งจริง), รายงานมูลค่าแยกหมวด
- **Out of Scope:** ส่ง email/sms จริง, ระบบ login/สิทธิ์, ระบบฐานข้อมูลภายนอก (SQL/NoSQL)

## 5. Functional Requirements (FR)
| รหัส | ความต้องการ | จาก Story |
|---|---|---|
| FR-01 | ระบบต้องอัปเดตสต็อกทันทีหลังบันทึกรับ/จ่าย | US-01 |
| FR-02 | ระบบต้องตรวจสต็อกก่อนจ่าย และปฏิเสธถ้าไม่พอ | US-01 |
| FR-03 | ระบบต้องแจ้งเตือนเมื่อสต็อกหลังจ่ายต่ำกว่า threshold | US-02 |
| FR-04 | ระบบต้องคำนวณและสรุปรายงานมูลค่าสต็อกรวมแยกตามหมวดหมู่สินค้าได้ | US-03 |
| FR-05 | ระบบต้องรองรับการกำหนดค่า threshold ขั้นต่ำแยกรายรายการสินค้าได้ | US-04 |
| FR-06 | ระบบต้องรองรับการเลือกและเปิด/ปิดช่องทางการแจ้งเตือน (Email / SMS) ได้อย่างอิสระ | US-05 |

## 6. Non-Functional Requirements (NFR)
| รหัส | มิติ | ความต้องการ (ต้องวัดได้) |
|---|---|---|
| NFR-01 | Performance | รายงานมูลค่าสต็อก 1,000 รายการเสร็จภายใน 1 วินาที |
| NFR-02 | Maintainability | เพิ่มช่องทางแจ้งเตือนใหม่ได้โดยไม่แก้ business logic เดิม |
| NFR-03 | Reliability | เมื่อเกิดข้อผิดพลาดในการคำนวณหรือส่งแจ้งเตือน ข้อมูลสต็อกเดิมต้องไม่เสียหาย |

## 7. Design Notes
- การแจ้งเตือนต้องแยกออกจาก business logic ของสต็อก
- คาดว่าจะมีหลายช่องทางแจ้งเตือน ควรออกแบบให้เพิ่มได้ง่าย
